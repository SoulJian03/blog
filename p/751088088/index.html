四、防火墙部署模式

1. 串接模式（Inline）：防火墙在流量路径上，流量必须经过防火墙。
   → 用于边界防护，能直接拦截恶意流量

2. 旁路模式（Out-of-band）：防火墙镜像流量进行分析，不直接拦截。
   → 用于监控和取证，不影响业务流量

3. 混部模式：生产网和蜜罐网混合，防火墙区分管理。
   → 蜜罐网络单独划分，防火墙监控蜜罐流量

传统防火墙规则（iptables 示例）：
  iptables -A INPUT -p tcp --dport 22 -j ACCEPT    # 允许 SSH
  iptables -A INPUT -p tcp --dport 80 -j ACCEPT    # 允许 HTTP
  iptables -A INPUT -j DROP                         # 默认拒绝

NGFW 策略（示例）：
  应用：SSH → 用户组：管理员 → 源：VPN 出口 → 动作：允许
  应用：HTTP → 用户组：所有人 → 源：Internet → 动作：允许
  应用：所有 → 用户组：所有 → 源：Internet → 动作：拒绝（默认）

规则优化原则：
1. 默认拒绝（Deny All），白名单放行
2. 最具体规则在最上面（先匹配具体，再匹配通用）
3. 定期审计规则（删除无用的/过期的规则）
4. 按用户组/应用做精细控制（NGFW）
5. 规则变更需审批和记录

攻击者绕过防火墙的常见方法：

1. 端口复用：
   • 使用 80/443 端口传输非 HTTP 流量
   • 在正常端口上运行隧道服务

2. DNS 隧道：
   • 企业防火墙通常放行 53 端口
   • 通过 DNS 查询携带数据

3. ICMP 隧道：
   • ICMP 通常不被防火墙检测
   • 通过 ping 包携带数据

4. 协议伪装：
   • SSH 流量伪装成 HTTPS（端口 443 + TLS 证书）
   • HTTP 请求中隐藏非 HTTP 数据

5. 分块传输：
   • 大 payload 拆成小片段，避免被深度检测

七、加固建议

1. 定期审计防火墙规则（每月/每季度）
2. 启用 NGFW 应用识别（识别异常应用流量）
3. SSL 解密（对加密流量做应用识别）
4. 分网段部署防火墙（东西向 + 南北向）
5. 防火墙日志接入 SIEM（关联分析）
6. 默认拒绝策略（Deny All by default）
7. 多因素认证保护防火墙管理口

发现：防火墙配置存在规则冗余，允许 10.0.0.0/24 网段访问所有端口（规则 #45），
实际业务只需 80/443 端口。同时发现非业务端口 7000（frp 通信端口）被放行。
影响：内网横向移动风险增加，非业务端口被利用时无法被防火墙拦截。
建议：按应用做精细规则；默认拒绝非业务端口；启用 NGFW 应用识别功能。

九、小结

防火墙是网络安全的"第一道门"，但传统包过滤已无法应对应用层攻击。NGFW 的核心价值是 L7 应用识别 + 用户级控制 + 内置 IPS。防守的核心是"默认拒绝 + 定期审计 + 应用识别"。
