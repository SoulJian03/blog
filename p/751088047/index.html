写在前面：合法学习边界

Windows 提权只用于授权靶场。对非授权主机提权可能触犯法律。

一、为什么 Windows 提权重要

获得初始 Shell（IIS AppPool/普通用户）后，需提权到 SYSTEM/Domain Admin 才能读取 SAM 数据库、安装后门、域横向移动。

# 查找可写服务
Get-CimInstance Win32_Service | Where-Object {$_.StartMode -eq "Auto"} | ForEach-Object {
  $path = (Get-CimInstance Win32_Service -Filter "Name='$($_.Name)'").PathName
  if (Test-Path $path -ErrorAction SilentlyContinue) {
    $acl = (Get-Item $path).GetAccessControl()
    if ($acl.Access -match "$env:USERNAME") { Write-Host "Writable: $path" }
  }
}

检测：
• Event ID 4672：特权服务登录（LSA 调用）
• 异常服务启动：新服务/修改的 binpath
• MSI 安装记录：普通用户安装 MSI 记录（Event ID 1033）

防御：
• 及时打补丁（Windows Update / WSUS）
• 启用 Credential Guard（防内存提取）
• ASR 规则：限制 Office/脚本创建子进程
• 最小权限：服务账户使用专用低权限账号

六、报告中的正确写法

发现：目标服务器 Windows 10 未安装 KB4012212 补丁，存在 PrintNightmare（CVE-2021-34527）提权漏洞。
利用方式：通过打印机驱动程序接口调用远程执行代码，直接获取 SYSTEM 权限。
影响：攻击者可在获取初始 shell 后，一步提权到 SYSTEM，读取 SAM 数据库并横向移动。
建议：立即安装 KB5003537 补丁；禁用 Print Spooler 服务（未使用打印时）；部署 EDR。

七、小结

Windows 提权核心是"补丁缺口 + 配置错误 + Token 操作"三件套。掌握系统信息收集→漏洞匹配→利用的链路，配合 PowerUp/AutoRCE 等自动化工具，提权效率大幅提升。防守核心是"及时打补丁 + Credential Guard + ASR 规则"。
