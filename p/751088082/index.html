Linux 应急响应处置全流程：事件确认、隔离、时间线、账号/进程/文件/启动项/日志排查、溯源、清理与加固。

写在前面：合法学习边界

应急响应面向真实事件，处置过程要保留证据、合法合规。本文是标准化流程与命令集合。

一、应急响应的目标

1
2
3
4
5

1. 遏制：阻止进一步扩散
2. 定位：找到入侵点与影响范围
3. 清除：清理后门与恶意文件
4. 恢复：恢复业务并加固
5. 溯源：还原攻击过程、留证追责

原则：先保全证据，再分析处置，不要在未取证前乱删乱改。

二、第一步：事件确认与隔离

1
2

确认现象：异常进程、CPU 飙高、异常外联、勒索提示、webshell 告警
隔离：断外网/断关键端口/快照镜像（保留证据）

影响与危害

不处置或处置不当：

1
2
3
4

攻击扩散到更多主机
业务中断、数据被窃
后门残留、反复入侵
缺乏证据导致无法追责

应急响应的价值就是把影响降到最低并保留证据。

三、第二步：建立时间线

1
2

记录发现时间、告警来源、现象
后续所有证据都标时间，便于还原攻击顺序

四、第三步：账号排查

1
2
3
4
5

cat /etc/passwd | grep -v nologin        # 异常账号
awk -F: '$3==0{print $1}' /etc/passwd     # UID 0 账号
cat /etc/shadow | grep -v '!\|\\*'        # 有密码可登录账号
last / lastlog                            # 登录记录
cat /etc/sudoers | grep -v '^#'           # 异常 sudo 权限

五、第四步：进程与网络连接排查

1
2
3
4
5
6

ps -ef --forest                          # 进程树，找异常进程
netstat -antlp | grep -iE 'ESTABLISHED|LISTEN'
ss -antlp
lsof -p <pid>                            # 异常进程打开的文件/连接
ls -l /proc/<pid>/exe                    # 进程对应可执行文件
cat /proc/<pid>/cmdline

关注：陌生进程、反向连接（外网 IP）、异常端口。

六、第五步：文件排查

1
2
3
4
5
6

# 近期修改文件
find / -mtime -3 -type f ! -path '/proc/*' ! -path '/sys/*' 2>/dev/null | head -100
find / -name '*.php' -mtime -3 2>/dev/null      # 新 webshell
find / -perm -4000 -type f 2>/dev/null          # suid 后门
ls -la /tmp /var/tmp /dev/shm                    # 临时目录藏毒
grep -rl 'eval(\|base64_decode\|assert' /var/www/html/ 2>/dev/null

grep 'Accepted' /var/log/secure

# 系统消息
tail -n 200 /var/log/messages
# Web 日志（webshell 访问、注入、上传）
grep -E 'POST|\.php' /var/log/nginx/access.log | tail
grep -E '\.jsp|\.php|cmd=|eval|select ' /var/log/apache2/access.log
# 历史命令
cat ~/.bash_history

九、第八步：溯源与结论

1
2
3

把时间线 + 日志 + 文件证据串起来：
攻击从哪来（IP/入口）→ 用什么漏洞 → 做了什么 → 留下什么
产出一份溯源报告（证据 + 时间线 + 处置建议）

十、第九步：清理与修复

1
2
3

清理：删恶意文件/账号/计划任务/服务，杀进程，补漏洞
加固：改口令、打补丁、收敛暴露面、上 WAF/EDR
复测：确认后门不再复活

十一、小结

Linux 应急响应是“隔离 → 时间线 → 五查（账号/进程/文件/启动项/日志）→ 溯源 → 清理加固”。核心是先把证据保住，再按套路排查。把这份命令清单练熟，遇到真实事件才不慌。
