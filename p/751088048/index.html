写在前面：合法学习边界

持久化与免杀技术只用于授权靶场。对非授权系统持久化可能触犯法律。

一、为什么需要持久化和免杀

C2 Beacon 上线后，如果只做一次性攻击，重启后连接就断了。持久化确保重启后还能连；免杀确保 EDR 不报。

# 1. 计划任务（推荐，隐蔽）
schtasks /create /tn "WindowsUpdateCheck" /tr "C:\Windows\Temp\beacon.exe" /sc onstart /ru SYSTEM

# 2. 注册表 Run 键
reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" /v "UpdateSvc" /t REG_SZ /d "C:\Windows\Temp\beacon.exe"

# 3. 服务
sc create UpdateSvc binpath="C:\Windows\Temp\beacon.exe" start=auto
sc start UpdateSvc

# 4. WMI 事件订阅（更隐蔽）
$filter = New-Object System.Management.ManagementEventWatcher
$filter.Query = New-Object System.Management.EventQuery("SELECT * FROM __InstanceCreationEvent WITHIN 10 WHERE TargetInstance ISA 'Win32_Process'")
$filter.Start()

四、免杀对抗层

1. shellcode 混淆

1
2
3
4
5
6

原理：对 shellcode 做异或/替换/分段，运行时还原执行。
工具：Veil、CS shellcode 混淆器、自定义异或。

示例（异或混淆）：
  原始 shellcode XOR 0x55 → 得到混淆后的字节序列
  写入文件时，先写入 XOR 还原代码，再写入混淆 shellcode

2. 进程注入

1
2
3
4

将 shellcode 注入到合法进程（explorer.exe / svchost.exe）中执行。
工具：mimikatz、PowerSploit、CobaltStrike execute-assembly

优点：无独立可执行文件落地，EDR 只能监控进程行为。

4. 无文件执行

不落地可执行文件，直接在内存中执行 payload。
工具：AMSI bypass + AMSI dll patch + 内存执行

方法：
  1. 用 PowerShell IEX 加载脚本（内存执行）
  2. 用 execute-assembly 直接加载 .NET 程序集
  3. 用 rundll32 加载 DLL 中的入口点

五、组合策略

1
2
3
4

推荐组合（生产环境）：
1. 持久化：计划任务 + 注册表 Run 双保底
2. 免杀：shellcode 异或混淆 + 进程注入 explorer.exe
3. C2：HTTPS 加密 + xray 混淆 + frp 代理
4. 备用：WMI 事件订阅 + 无文件执行
5. 多持久化点互为备份，避免单点被发现后全线崩溃

检测点：
• 异常进程父子关系（explorer 创建 powershell）
• 注册表 Run 键新增条目
• 计划任务新建/修改
• WMI 事件订阅
• 异常外联（DNS 高频、HTTPS 到陌生 IP）
• 内存异常（大量非正常 DLL 加载）
• AMSI 绕过检测（EDR 检查 AMSI buffer 修改）

七、防御

1
2
3
4
5

8

1. EDR（行为检测）：进程注入、异常父子关系、内存操作
2. ASR 规则：限制 Office/脚本创建子进程
3. 注册表审计：监控 Run 键变更
4. 计划任务审计：监控新任务创建
5. 网络隔离：禁止内网主机直连公网
6. 最小权限：禁止普通用户创建服务/计划任务
7. Credential Guard：防内存提取
8. AMSI：阻止脚本执行（防 AMSI 绕过）

八、小结

持久化与免杀是 C2 维持的关键。核心原则：多层持久化（至少2个独立路径）+ 免杀组合（混淆+进程注入+C2加密）+ 定时轮换。防守核心是 EDR + ASR + 行为审计。
