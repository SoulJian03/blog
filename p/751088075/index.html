Log4j2（CVE-2021-44228 日志4j）漏洞完整复现：原理、利用方式、版本影响、绕过路径、临时缓解与修复加固。

写在前面：合法学习边界

Log4j2 利用只用于授权靶场。对真实系统发送 JNDI 注入可能触犯法律。

一、原理

Log4j2 在记录日志时会处理字符串中的 ${jndi:...} 语法（用于动态变量替换）。攻击者在任意可写入日志的位置（Header/参数/Cookie）注入 ${jndi:ldap://...} 后，Log4j 会自动发起 JNDI 请求，加载远程恶意 Java 类执行。

立即修复：
1. 升级 Log4j ≥ 2.17.1（推荐 2.17.2）
2. 临时缓解（无法立即升级时）：
   启动参数：-Dlog4j2.formatMsgNoLookups=true
   删除 JndiLookup.class（从 log4j-core.jar 中删除）
3. WAF 规则：拦截所有含 ${jndi、${jdbc、${jms 的请求

长期加固：
4. 使用 SLF4J 统一日志接口
5. 监控 Java 应用出站 LDAP/RMI 连接
6. 定期扫描 Log4j 版本

八、报告中的正确写法

1
2
3
4

发现：目标应用使用 Log4j 2.14.1，存在 CVE-2021-44228（Log4Shell）远程代码执行漏洞。
利用方式：通过 User-Agent 头注入 ${jndi:ldap://...}，触发 JNDI 回调加载远程恶意 Java 类，实现 RCE。
影响：攻击者无需认证即可在 Java 进程上下文中执行任意代码，获取服务器完整控制权。
建议：立即升级 Log4j ≥ 2.17.1；临时缓解加 -Dlog4j2.formatMsgNoLookups=true 启动参数；WAF 拦截含 ${jndi 请求。

九、小结

Log4j2 漏洞是"史上最强"的 Java 漏洞——无需认证、无需权限、所有 Log4j 2.x < 2.17.1 全受影响。修复的核心是升级版本 + 临时缓解参数。防守的核心是 WAF 拦截 + 网络出站限制。
